Kubernetes — before you start
Local cluster prep (minikube / kind)
🔔
All images use :latest tag and imagePullPolicy: IfNotPresent. Build and load your images into the cluster before applying, or update the image: fields to point to your own registry.
📦
Load images into kind: 
kind load docker-image cart-service:latest
kind load docker-image payment-service:latest
kind load docker-image finance-service:latest
kind load docker-image ybrainy-eureka:latest
kind load docker-image ybrainy-api-gateway:latest
Or for minikube: 
minikube image load cart-service:latest
minikube image load payment-service:latest
minikube image load finance-service:latest
minikube image load ybrainy-eureka:latest
minikube image load ybrainy-api-gateway:latest

Prerequisites inside WSL
▶
ℹ
Install on WSL (Ubuntu recommended) before running the pipeline. Docker Desktop with WSL integration also works.
Docker Engine kubectl kind minikube
✅
Minikube (WSL) recommended: use the docker driver so Jenkins can run minikube image load against the same Docker daemon. 
minikube start --driver=docker

# Verify kubectl uses minikube
kubectl config current-context
kubectl get nodes
2
Run Jenkins in Docker (recommended)
▶
⚠
The stock jenkins/jenkins:lts-jdk17 image does not include docker, kubectl, minikube, or kind. Use the included tools image at k8s/jenkins/Dockerfile.

From WSL — builds the Jenkins tools image, then runs Jenkins with Docker socket + kubeconfig mounted:

# Build a Jenkins image that contains docker + kubectl + minikube + kind
docker build -t payment-jenkins:lts-tools -f k8s/jenkins/Dockerfile .

docker volume create jenkins_home

# Run Jenkins (local/dev). Running as root avoids docker.sock permission issues.
docker run -d --name jenkins \
  -u root \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v $HOME/.kube:/var/jenkins_home/.kube:ro \
  payment-jenkins:lts-tools

Open the Jenkins UI and retrieve the initial admin password:

http://localhost:8080

docker exec jenkins cat \
  /var/jenkins_home/secrets/initialAdminPassword

4
Run the job — Build with Parameters
▶

Click Build with Parameters and configure:

Parameter Description
CLUSTER_TYPE minikube — images on same machine as Jenkins (loads via minikube image load)
kind — same, for kind
none — images already in a registry or pullable
IMAGE_TAG Default: latest
DOCKER_REGISTRY Leave empty for local clusters. Set to e.g. ghcr.io/<org> for a real registry (requires docker login on the agent).
DOCKER_REGISTRY_CREDENTIALS_ID Optional. Create a Username with password credential in Manage Jenkins → Credentials and paste its credentialsId here to enable automatic docker login.
5
Notes & common gotchas
▶
⚠
External images not built by this pipeline: ybrainy-eureka:latest and ybrainy-api-gateway:latest are referenced in k8s/eureka.yaml and k8s/api-gateway.yaml but are not built by this repo's pipeline. Make sure those images exist in your cluster (loaded) or in your registry before applying.
🧩
Minikube tip: If you choose CLUSTER_TYPE=minikube, use minikube start --driver=docker. This makes minikube image load work reliably from the Jenkins container (same Docker daemon via /var/run/docker.sock).
🔒
Kubeconfig unreachable from inside Docker: If Jenkins runs in Docker and cannot reach your cluster, verify the mounted $HOME/.kube has the correct context and valid certificates for your local cluster.
